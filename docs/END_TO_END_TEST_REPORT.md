## Confirmed defects and recommended fixes

Five categories below consolidate repeated observations: concurrent acknowledgement/assignment are one conflict-handling defect; three misleading-copy surfaces are one wording defect. A successful state mutation does not make its incorrect explanatory text pass.

### D01 — CSV formula protection bypass

**Severity: Medium.** A permitted municipal note prefixed with a tab escapes the export protection applied to a plain formula. A spreadsheet may interpret it as a formula; execution was not attempted.

**Reproduce:** Acknowledge an owned NEW issue with note `\t=SUM(1,1)`, then export `/api/v1/admin/audit.csv?issueRef=QA-A-000010`. Parse the CSV: the cell begins U+0009 then `=`, without a protective apostrophe. Plain `=SUM(1,1)` on a comparator issue is protected.

**Expected / observed:** Expected every dangerous whitespace/control-prefixed expression to be neutralized in export, with original history unchanged. Observed HTTP200 acknowledgement/export and unneutralized parsed cell.

**Source and cause:** `backend/src/main/java/com/civictrack/audit/AuditCsv.java:44` only tests the first character. This source-supported cause explains the bypass.

**Suggested fix and regression:** Harden the serializer consistently for dangerous control/whitespace prefixes on all untrusted cells; preserve stored original text. Regress via real acknowledgement/export and parsed-cell assertions for tab/CR/LF/space plus =,+,-,@ and normal quoted text.

**Evidence:** [admin-findings.md](../artifacts/e2e/QA-20261108T001350/admin-findings.md), [admin-csv-proof.json](../artifacts/e2e/QA-20261108T001350/admin-csv-proof.json), [admin-api-results.json](../artifacts/e2e/QA-20261108T001350/admin-api-results.json).

### D02 — Tied audit events skipped/duplicated

**Severity: Medium.** An administrator can miss an audit event and see another twice while paging a stable dataset.

**Reproduce:** Use prepared QA-A-000011 with125 distinct tied status notes plus one real acknowledgement. Read50-row pages at offsets0/50/100, without intervening writes.126 rows are received but125 notes are unique: tied-50 duplicates and tied-125 is missing.

**Expected / observed:** Expected126 unique reachable events. Observed one duplicate/one omission under actual API pagination; independent SQL established the stable fixture count.

**Source and cause:** `backend/src/main/java/com/civictrack/audit/AuditQueries.java:68` and`:77` order by time/kind/issue only. Equal keys have no unique event tie breaker; this source-supported ordering explains the result.

**Suggested fix and regression:** Carry source primary keys through the union and add stable unique `(kind,event-id)` ordering to page/export. Add a >2-page stable dataset with all other sort keys tied and assert exact once-only traversal.

**Evidence:** [admin-findings.md](../artifacts/e2e/QA-20261108T001350/admin-findings.md), [admin-api-results.json](../artifacts/e2e/QA-20261108T001350/admin-api-results.json).

### D03 — Concurrent work actions return generic500

**Severity: Medium.** A stale municipal actor receives a server-error retry prompt rather than an actionable conflict, even though another actor already completed the action. Data remained atomic.

**Reproduce:** On distinct owned NEW/ACKNOWLEDGED issues, hold a SQL row lock, launch two permitted acknowledge/assign requests, then release it. Each pair returns[200,500]. SQL/history show only one target transition.

**Expected / observed:** Expected one success and one409 with reload guidance; observed generic500 loser. No duplicate history or corrupted assignment was observed.

**Source and cause:** `Issue` optimistic version conflict reaches `backend/src/main/java/com/civictrack/common/error/GlobalExceptionHandler.java:319` generic fallback. Server excerpt confirms ObjectOptimisticLockingFailureException/StaleObjectStateException; no mapped conflict handler.

**Suggested fix and regression:** Map optimistic-lock conflicts to409 with reload guidance, or consistently serialize transition reads while retaining policy checks. Add two-transaction acknowledge/assign regressions checking loser response, one history transition and notification atomicity.

**Evidence:** [supervisor-staff-audit.md](../artifacts/e2e/QA-20261108T001350/supervisor-staff-audit.md), [supervisor-concurrency.json](../artifacts/e2e/QA-20261108T001350/supervisor-concurrency.json), [supervisor-concurrency-server-excerpt.txt](../artifacts/e2e/QA-20261108T001350/supervisor-concurrency-server-excerpt.txt).

### D04 — Visually blank Unicode configuration label

**Severity: Low.** A department can be saved with an empty-looking name, making lists and selectors harder to use.

**Reproduce:** PUT an existing owned department name as three U+00A0 NBSP characters with parent/head null. Observe204 and stored length3. The audit restored the ordinary synthetic name afterward.

**Expected / observed:** Expected400 and no saved blank label. Actual audited update retained three NBSP characters.

**Source and cause:** `backend/src/main/java/com/civictrack/config/AdminConfigurationController.java:85`/`:90` use @NotBlank and strip(), which do not reject this NBSP-only input. Similar fields exist but this specific input was tested only on a department.

**Suggested fix and regression:** Use shared Unicode-aware visible-text validation/normalization before saving. Regress NBSP, em-space, tabs, BOM and mixed whitespace; check meaningful400 and no audit write after refusal.

**Evidence:** [admin-findings.md](../artifacts/e2e/QA-20261108T001350/admin-findings.md), [admin-api-results.json](../artifacts/e2e/QA-20261108T001350/admin-api-results.json).

### D05 — Verification copy confuses timeout, confirmation and closure

**Severity: Medium.** Citizens can be misled about whether a person confirmed repair and whether a vote immediately closes the complaint. Actual lifecycle and notification outcomes were correct.

**Reproduce:** Open a pending original-reporter verification page, then account preferences. Read “needed to close it”, “it counts as fixed” and “counts as confirmed after the deadline”. A direct attempt to mute VERIFY_REQUESTED also returns409 using the false confirmation description; prior preference remains intact.

**Expected / observed:** Expected resolution to be distinguished from later closure and timeout resolution from citizen confirmation. Observed three stale wording surfaces; no false verification row or incorrect lifecycle was established.

**Source and cause:** `frontend/src/app/me/verify/[id]/page.tsx:304`/`:309`, `frontend/src/components/account/ProfileSettings.tsx:21`/`:23`, and `backend/src/main/java/com/civictrack/user/ProfileService.java:79` contain the stale wording. Cause is source-confirmed text inconsistency.

**Suggested fix and regression:** Describe votes as marking resolved; describe timeout accurately as resolution without citizen confirmation where policy permits it. Keep lifecycle rules unchanged. Regress visible tally/preferences/refusal wording plus preserved timeout and vote behavior.

**Evidence:** [root-findings.json](../artifacts/e2e/QA-20261108T001350/root-findings.json), [principal-verification-before-vote.jpg](../artifacts/e2e/QA-20261108T001350/principal-verification-before-vote.jpg), [backend-defects.md](../artifacts/e2e/QA-20261108T001350/backend-defects.md), [backend-live-security.json](../artifacts/e2e/QA-20261108T001350/backend-live-security.json).
